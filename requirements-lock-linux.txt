# Production dependency lock (Linux / VPS).
#
# requirements.txt says what the application needs, in ranges. That is right
# for someone installing from source, and wrong for a server: the deploy script
# runs `pip install -r requirements.txt` on every update, so every upstream
# release reached production unreviewed — the running set had drifted to
# versions nobody had chosen. Nothing was broken by it, but that was luck
# rather than control.
#
# Used as a CONSTRAINTS file, not a requirements file:
#
#     pip install -r requirements.txt -c requirements-lock-linux.txt
#
# Constraints cap versions without forcing anything to be installed, so adding
# a dependency to requirements.txt still works; it simply arrives unpinned
# until this file is regenerated.
#
# Captured from the VPS on 2026-08-12 with `pip check` clean and the service
# healthy — a known-good set, not a wish list.
#
# To take upstream updates deliberately: drop the pin you want to move, deploy,
# confirm the service is healthy, then regenerate with
#     pip freeze | sort
# The operator's own tools (py-spy) are left out; this file describes the
# application's dependencies.
