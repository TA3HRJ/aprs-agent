# Audit — 2026-08-15, v3.2.38

**Report only. Nothing in this file has been applied.** Every number was
measured on the live server or in a browser against the live public site; where
a figure is an estimate it says so.

A note on the method before the findings: the first pass of this audit produced
three findings that were wrong, and they were wrong in the direction that
flatters the auditor — unused imports that turned out to be aliased, and a
"291-line function" that is five lines. They were caught by checking each one
before writing it down. What survives below has been verified individually.

---

## 1 · Compression — the largest single win, and it is one config line

The app gzips the shell itself (`_gzipped_index`). **Nothing else is
compressed**, because Apache's `deflate.conf` lists `text/html`, `text/css`,
`application/javascript` and friends — and not `application/json`.

Measured, real payloads, gzip level 6:

| endpoint | now | gzipped | ratio | cost to compress |
|---|---|---|---|---|
| `/api/stations` | 932,033 B | **113,135 B** | **8.2×** | 28.7 ms |
| `/api/missing` | 138,127 B | 24,726 B | 5.6× | 3.5 ms |
| `/api/silence` | 27,652 B | 5,001 B | 5.5× | 0.8 ms |
| `/api/prop` | 6,403 B | 1,421 B | 4.5× | 0.2 ms |

Confirmed end to end from the browser: on the live site the shell arrives at
57.7 KB transferred against 185.7 KB decoded (gzip working, 3.2×), while the
API responses show transferred ≈ decoded — no compression at all.

**One line in the Apache config covers all of it:**
`AddOutputFilterByType DEFLATE application/json`

Doing it in aiohttp instead would also work and would cover the nginx fallback
path on :8443/:9443, which Apache's config does not touch. Either is small; the
Apache line is smaller, the application-level one is more complete.

## 2 · What one open tab actually costs

Measured on the live public site, one tab, 117 seconds, no interaction:

```
stations : 19 requests   5 full bodies   14 cheap 304s   4,569 KB
silence  :  8 requests                                     218 KB
missing  :  7 requests   (no ETag — every one a full body) 945 KB
------------------------------------------------------------------
total    : 5,732 KB in 117 s   ->   ~2.9 MB per minute per viewer
```

Three separate observations in that table:

**The ETag on `/api/stations` works** — 14 of 19 requests cost nothing. It is
the 5 that got through that carry 4.5 MB, because the slim-cache token turns
over as the registry updates, so any poll spaced further apart than the cache
window pays full price.

**`/api/missing` has no ETag at all.** 135 KB, seven times, every one a full
body. It is served from the same registry as `/api/stations`, which already has
a cache token to reuse.

**Compression would take the whole table down by roughly 6×** — about
950 KB/min instead of 2.9 MB — before any other change.

## 3 · The map polls the whole world to draw one screen

`/api/stations` is requested with no `bbox` on essentially every poll: in the
Apache log, **2,739 requests with no query string against 4 with a bbox**. The
server caps the answer at 4,000 stations and the client clusters above 2,000,
so most of what arrives is aggregated into numbered badges the moment it lands.

The bbox parameter already exists and works. Nothing uses it at the zoom levels
where it would help most.

*Estimate, not measured:* at typical zoom a viewport holds a low hundreds of
stations rather than 4,000, so this is plausibly another 5-10× on top of
compression. It needs measuring against real viewports before anyone commits to
that number.

## 4 · Payload contents

`/api/silence` was cut 37× on 2026-08-14 by sending only the cells the client
draws (2,135 → 34). The same question has not been asked of the others:

- **`last_seen` and `last_seen_ago_s` are both sent** for every station —
  92,000 and 83,390 bytes respectively in a 1.24 MB response. The second is
  derivable from the first and the current time. **~6.4% of the payload.**
- Empty-valued keys were dropped in v3.2.29 (city, district, `self_beacon`,
  most `ai_org`), which took 1,305,109 B to 932,205 B. That work is done.

## 5 · Code size

```
                        lines     bytes
gui.py                   3,066   137,042    feature-frozen at 2.8.0
web_gui.py               2,925   137,254
static/index.html        2,612   190,075
station_db.py            1,892    90,040
packet_parser.py           748    24,606
config.py                  466    17,133
aprs_connection.py         270     9,322
extensions/ (10 files)   1,965    68,821
------------------------------------------
Python total            11,816 lines
```

**`gui.py` is 26% of the Python and has been feature-frozen since 2.8.0.** It
is not dead — it ships and works — but every future change to shared behaviour
carries the question of whether the desktop GUI needs it too. That is a
maintenance decision, not a defect, and it is the single largest lever on code
volume if the answer is ever "no".

`static/index.html` breaks down as 65% JavaScript, 15% CSS, 15% comments
(27 KB), 5% markup. The comments are this project's record of why things are the
way they are and should not be minified away; they cost 27 KB uncompressed and
almost nothing after gzip.

**No dead JavaScript.** 108 functions defined, every one referenced.

**Four genuinely unused imports**, verified individually after three others
turned out to be aliased and fine:

```
extensions/logger_ext.py    aprslib
extensions/imap_ext.py      time
extensions/telegram_ext.py  time
extensions/whatsapp_ext.py  time
```

Four lines. Worth deleting, worth nothing in performance.

## 6 · Ordered by return per effort

| # | change | effect | risk | effort |
|---|---|---|---|---|
| 1 | gzip on `application/json` | **~6× less traffic**, everywhere | very low | one line |
| 2 | ETag on `/api/missing` | 945 KB → near zero per tab per 2 min | low | small |
| 3 | drop `last_seen_ago_s`, derive client-side | ~6% of the largest payload | low | small, touches client |
| 4 | map asks by `bbox` when clustered | plausibly 5-10× on top of #1 | medium | real work, needs measuring first |
| 5 | delete four unused imports | none | none | four lines |

**#1 alone is worth more than #2 through #5 combined**, and it is the only one
that requires no code change at all.

## 7 · Things deliberately not in this report

- **Anything about the desktop GUI's internals.** It is frozen; auditing it
  invites changing it.
- **Minification of `index.html`.** It would strip the comments, which are the
  most valuable part of the file, to save bytes that gzip already handles.
- **Micro-optimisation of the registry walk.** The 7.85 s rebuild tail recorded
  in F-36 is still unexplained, and guessing at it is what the last three
  attempts did. It needs instrumentation inside the build, not a suggestion in
  an audit.
- **The `daily_limit` counter living in memory.** Noted here so it is not
  forgotten: it resets on restart, which weakens it as a billing guard. Small,
  and not measured against anything, so it is a note rather than a finding.
