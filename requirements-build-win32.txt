# Exact build environment for the Windows (32-bit) executables.
#
# requirements.txt states what the application needs; this file states what a
# release was actually built against, so a build can be reproduced later
# instead of drifting with whatever PyPI serves that day.
#
# Interpreter: CPython 3.13.9, 32-bit (python.org "Windows installer (32-bit)")
#
#   2026-08-26: the v3.2.97 build was made on CPython 3.13.15 32-bit, because
#   that is what winget serves for 3.13 now and 3.13.9 is no longer offered.
#   Same minor, same architecture, and every dependency below resolved to the
#   pinned version with a win32 wheel. Recorded rather than glossed: this file
#   is worth having only while it says what a release was ACTUALLY built with.
#
#   Recreate with:
#     C:\Python313-32\python.exe -m pip install -r requirements-build-win32.txt
#     C:\Python313-32\python.exe -m PyInstaller aprs_agent.spec --noconfirm
#
# The cryptography ceiling, stated correctly:
#
#   atproto 0.0.69 requires cryptography >=41.0.7,<47. An earlier note in this
#   file claimed the cap was <46 and applied on every architecture — that was
#   wrong. It came from reading a pip backtracking log: because cryptography
#   48 has no 32-bit Windows wheel, pip searched older atproto releases and
#   printed *their* constraints, which are the <46 lines. The current release
#   allows 46.x.
#
#   What actually limits this build is the 32-bit wheel: within atproto's <47
#   range, the newest cryptography with a win32 wheel is 46.0.3, so this file
#   could move 45.0.7 -> 46.0.3. Above that, cryptography publishes win32
#   wheels only up to 48.0.0, and none after — so if atproto ever raises its
#   cap past 48, 32-bit Windows means dropping Bluesky or moving to 64-bit.
#   (The Linux/VPS side runs 46.0.7, which needs no win32 wheel.)
